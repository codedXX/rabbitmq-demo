# RabbitMQ 生产者确认与消费者重连测试文档

## 1. 测试目标

使用 ApiFox 验证当前项目中的以下功能：

1. 生产者 Confirm：消息是否成功到达交换机。
2. 生产者 Return：消息到达交换机后，是否成功路由到队列。
3. 生产者发送失败后的重试机制。
4. 消费者连接 RabbitMQ 失败后的自动重连机制。

Confirm 和 Return 可以同时开启，二者负责不同阶段：

```text
生产者 -> 交换机：ConfirmCallback
交换机 -> 队列：ReturnsCallback
```

## 2. 当前项目配置

### 2.1 RabbitMQ 连接信息

```yaml
host: localhost
port: 5672
username: guest
password: guest
```

### 2.2 RabbitMQ 拓扑信息

| 类型 | 名称 |
|---|---|
| 交换机 | `demo.exchange` |
| 交换机类型 | `direct` |
| 队列 | `demo.queue` |
| 路由键 | `demo` |

当前绑定关系：

```text
demo.exchange --(demo)--> demo.queue
```

### 2.3 生产者确认配置

```yaml
spring:
  rabbitmq:
    publisher-confirm-type: correlated
    publisher-returns: true
    template:
      retry:
        enabled: true
        initial-interval: 1000ms
        multiplier: 1
        max-attempts: 3
```

含义：

- `publisher-confirm-type: correlated`：开启带消息关联数据的 Confirm。
- `publisher-returns: true`：开启 Return。
- `max-attempts: 3`：生产者一次发送总共尝试 3 次，包括第一次发送。

## 3. 启动前检查

### 3.1 启动 RabbitMQ

确认 RabbitMQ 正在运行，并且管理页面可以访问。默认管理地址一般是：

```text
http://localhost:15672
```

确认 RabbitMQ 页面中存在：

- `demo.exchange`，类型为 `direct`
- `demo.queue`
- `demo.exchange` 到 `demo.queue` 的绑定，路由键为 `demo`

如果交换机和队列不存在，先启动 Spring Boot 项目，让 `@RabbitListener(bindings = ...)` 自动声明它们。

### 3.2 启动 Spring Boot 项目

项目端口为：

```text
8081
```

启动成功后，接口地址为：

```text
http://localhost:8081/messages
```

修改配置后必须重启 Spring Boot 项目。

## 4. ApiFox 请求配置

在 ApiFox 中创建一个请求：

```text
请求方式：POST
请求地址：http://localhost:8081/messages
```

请求头：

| 参数 | 值 |
|---|---|
| `Content-Type` | `text/plain` |

请求体：

```text
Body -> Raw -> Text
```

示例内容：

```text
hello-rabbitmq
```

注意：当前接口只接收 `text/plain`，不要选择 JSON，否则可能返回 `415 Unsupported Media Type`。

## 5. 测试一：正常发送和 Confirm 成功

### 5.1 测试目的

验证消息可以从生产者到达交换机，并最终被消费者消费。

### 5.2 操作步骤

1. 启动 RabbitMQ。
2. 启动 Spring Boot 项目。
3. 在 ApiFox 中按照第 4 节配置请求。
4. 请求体填写：

   ```text
   confirm-test
   ```

5. 点击发送。

### 5.3 ApiFox 预期结果

HTTP 状态码：

```text
200 OK
```

响应内容：

```text
sent: confirm-test
```

### 5.4 控制台预期日志

Confirm 成功日志：

```text
publisher confirm success, correlationId=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

消费者日志：

```text
received message: confirm-test
```

### 5.5 测试结论

出现 `publisher confirm success`，说明消息已经成功到达交换机。

出现 `received message`，说明消息又成功路由到了队列，并被消费者消费。

## 6. 测试二：Return 路由失败

### 6.1 测试目的

验证消息虽然到达了交换机，但由于路由键不匹配，无法路由到队列时会触发 `ReturnsCallback`。

### 6.2 临时修改生产者路由键

当前生产者使用：

```java
RabbitMqConfig.ROUTING_KEY
```

临时将 `MessageProducer` 中的发送代码改为：

```java
rabbitTemplate.convertAndSend(
        RabbitMqConfig.EXCHANGE_NAME,
        "invalid-key",
        message,
        correlationData
);
```

消费者中的绑定仍然保持：

```java
key = RabbitMqConfig.ROUTING_KEY
```

也就是消费者仍然监听路由键 `demo`，生产者改为发送 `invalid-key`。

修改后重启 Spring Boot 项目。

### 6.3 ApiFox 操作

发送请求，请求体填写：

```text
return-test
```

### 6.4 ApiFox 预期结果

接口通常仍然返回：

```text
200 OK
sent: return-test
```

因为 Return 回调是异步执行的，不会自动把路由失败转换成接口异常。

### 6.5 控制台预期日志

Confirm 仍然可能成功：

```text
publisher confirm success, correlationId=...
```

同时出现 Return 日志：

```text
publisher return, exchange=demo.exchange, routingKey=invalid-key, replyCode=312, replyText=NO_ROUTE
```

此时不应该出现：

```text
received message: return-test
```

### 6.6 测试结论

这个结果说明：

```text
Confirm 成功：交换机收到了消息
Return 触发：交换机没有找到匹配的队列绑定
```

测试完成后，必须把生产者路由键改回：

```java
RabbitMqConfig.ROUTING_KEY
```

然后重启项目。

## 7. 测试三：生产者发送失败重试

### 7.1 测试目的

验证 `RabbitTemplate` 发送消息连接失败时，会按照配置进行 3 次尝试。

### 7.2 操作步骤

1. 启动 RabbitMQ。
2. 启动 Spring Boot 项目。
3. 保持 Spring Boot 项目运行。
4. 停止 RabbitMQ。
5. 使用 ApiFox 发送：

   ```text
   producer-retry-test
   ```

### 7.3 预期结果

ApiFox 请求会等待一段时间，最后返回失败，通常是：

```text
500 Internal Server Error
```

控制台中，生产者请求线程通常是：

```text
[nio-8081-exec-*]
```

并且可以看到：

```text
Attempting to connect to: [localhost:5672]
```

以及：

```text
RetryTemplate.doExecute
```

因为配置为：

```yaml
max-attempts: 3
```

所以一次 ApiFox 请求最多尝试 3 次，不是无限重试。

### 7.4 注意事项

停止 RabbitMQ 后，消费者也会不断尝试重连。消费者日志通常包含：

```text
[tContainer#*]
SimpleMessageListenerContainer
Restarting Consumer
```

这些是消费者自动重连，不是生产者的 3 次发送重试。

## 8. 测试四：消费者自动重连

### 8.1 测试目的

验证 RabbitMQ 停止后，`@RabbitListener` 创建的消费者容器会在后台持续尝试恢复连接。

### 8.2 操作步骤

1. 启动 RabbitMQ。
2. 启动 Spring Boot 项目。
3. 不调用 ApiFox 接口。
4. 停止 RabbitMQ。

### 8.3 预期日志

```text
Consumer raised exception
Restarting Consumer
Attempting to connect to: [localhost:5672]
Failed to check/redeclare auto-delete queue(s)
```

日志线程通常是：

```text
[tContainer#*]
```

### 8.4 恢复测试

1. 重新启动 RabbitMQ。
2. 等待 Spring Boot 控制台出现连接成功日志。
3. 使用 ApiFox 再发送一条正常消息。

预期消费者恢复工作，并出现：

```text
received message: recovery-test
```

## 9. 日志快速判断表

| 日志或线程 | 含义 |
|---|---|
| `publisher confirm success` | 消息到达交换机 |
| `publisher confirm failed` | 交换机没有确认消息 |
| `publisher return` | 消息无法路由到队列 |
| `RetryTemplate.doExecute` | 生产者发送重试 |
| `nio-8081-exec-*` | ApiFox 请求对应的生产者线程 |
| `tContainer#*` | 消费者监听和自动重连线程 |
| `received message` | 消费者已经收到消息 |
| `replyCode=312` | 路由失败，通常是 `NO_ROUTE` |

## 10. 常见问题

### 10.1 ApiFox 返回 415

检查请求头是否为：

```text
Content-Type: text/plain
```

请求体不要使用 JSON。

### 10.2 没有 Confirm 日志

检查：

1. 是否重启了 Spring Boot 项目。
2. RabbitMQ 是否正常运行。
3. `publisher-confirm-type` 是否为 `correlated`。
4. 是否实际调用了 `/messages` 接口。

### 10.3 没有 Return 日志

检查：

1. 是否设置了：

   ```java
   rabbitTemplate.setMandatory(true);
   ```

2. 交换机名称是否正确。
3. 生产者路由键是否与消费者绑定键不同。
4. 是否重启项目使配置生效。

### 10.4 只有 Confirm，没有消费者日志

这通常表示消息到达了交换机，但没有路由到队列。重点检查：

- 交换机名称
- 交换机类型
- 路由键
- 队列绑定关系

### 10.5 `Attempting to connect` 一直增加

如果线程是 `[tContainer#*]`，这是消费者自动重连，默认会持续进行，直到 RabbitMQ 恢复或 Spring Boot 停止。

如果线程是 `[nio-8081-exec-*]`，则通常是某一次 ApiFox 请求触发的生产者连接和重试。

## 11. 测试结束后的恢复操作

1. 确认 `MessageProducer` 使用：

   ```java
   RabbitMqConfig.ROUTING_KEY
   ```

2. 确认消费者绑定键仍然是：

   ```java
   key = RabbitMqConfig.ROUTING_KEY
   ```

3. 重新启动 RabbitMQ。
4. 重启 Spring Boot 项目。
5. 使用 ApiFox 发送一条正常消息，确认最终日志为：

   ```text
   publisher confirm success
   received message: ...
   ```
